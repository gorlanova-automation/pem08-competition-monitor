# PEm08 — анализ публичных лендингов платформ автоматизации

Учебная адаптация [Toxap/pem08](https://github.com/Toxap/pem08) для Елены Горлановой. Код исходного проекта сохранён и доработан; авторство исходной основы не присваивается.

Материалы: первые экраны **n8n, Make, Zapier**, снятые 28 октября 2026 года. Это демонстрация анализа материалов лендинга, а не достоверный рейтинг продуктов или рынка. Скриншоты настоящие, без генерации и изменения пикселей. Источники и время — в `data/captures.json`.

## Что изменено

- ProxyAPI, асинхронные вызовы, строгая проверка JSON. Неполный ответ не превращается в фиктивный успех.
- Поля `design_score`, `animation_potential`, `evidence_limitations` в API, веб-интерфейсе и desktop-клиенте. По одному тексту дизайн не оценивается (`null`); по изображению оценка субъективна. Статичный снимок не доказывает качество анимации.
- Секреты и входные материалы не выводятся сервисом модели в лог. Дописан `.gitignore`, ключей в репозитории нет.
- Проверка изображения по фактическому формату, лимит 5 МБ; экранирование строк модели перед вставкой в HTML.
- Совместимые маршруты `/analyzetext`, `/analyzeimage`, `/parsedemo` и исходные варианты с подчёркиваниями.
- Доступ сервера по умолчанию только `127.0.0.1:18104`; URL парсинга ограничены тремя HTTPS-лендингами.

## Запуск

Python 3.12, Windows 10. Установите зависимости в отдельное окружение:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создайте `.env` по `env.example.txt`, задайте собственный `PROXY_API_KEY`. Не отправляйте `.env` и не включайте его в сборку. Во время проверок ключ передавался только через окружение процесса из существующего локального файла владельца.

```powershell
.venv\Scripts\python.exe -m uvicorn run:app --host 127.0.0.1 --port 18104
```

Откройте `http://127.0.0.1:18104/`, документация — `/docs`, состояние — `/health`.

## Сбор данных и границы проверки

В выполненной проверке использован режим `PARSER_MODE=capture`: `/parsedemo` читает настоящий сохранённый скриншот и текст из `data`, отправляет их модели и сохраняет результат в историю. Сбор сделан через `cua_repl` в разрешённом Chrome-профиле пользователя. Режим явно отражён в `/health` и ответе `/parsedemo`.

В проекте сохранён режим `PARSER_MODE=selenium` для отдельного самостоятельного запуска. Он создаёт изолированный headless Chrome, без подключения пользовательских профилей. **Живой запуск Selenium в этой работе не проверялся.** Проверку по сохранённым снимкам нельзя выдавать за Selenium-сбор. URL задаются в `backend/config.py`.

Cursor установлен и авторизован, но захват его окна недоступен. Код доработан через Codex; работа внутри агента Cursor не заявляется. Пользователь предложил VS Code как запасной редактор.

## Проверки и desktop

```powershell
.venv\Scripts\python.exe -m unittest -v test_project
.venv\Scripts\python.exe verify_live.py
.venv\Scripts\python.exe -m pip install -r desktop/requirements.txt
.venv\Scripts\python.exe desktop/build.py
```

`verify_live.py` делает **платные API-запросы**: текст и изображение каждого из трёх источников и один parse-capture; результаты — `evidence/live_tests.json`. Используйте только свои или публичные несекретные данные.

Desktop-клиент требует отдельно запущенный backend. Итоговая сборка — `desktop/dist/competitionmonitor.exe`; ключ не встроен. PyQt6 и Qt закреплены на совместимых версиях после ошибки загрузки QtWidgets первой сборки. Проверка `--smoke-test <путь.json>` создаёт компоненты Qt вне экрана и проверяет backend; это **не визуальная проверка окна и не её скриншот**. Фактический итог такой проверки сохраняется в `evidence/desktop_smoke.json` после успешного выполнения.

В `evidence` сохранены реальные результаты, автотесты и скрины интерфейса. Файлы `initial_*` — ранние результаты до исправлений: в частности, cookie-окно Make перекрывало лендинг. Они не относятся к итоговому сравнению. Идеи и оценки модели требуют проверки человеком; непроверенные маркетинговые заявления источника не становятся независимыми фактами.

Ни сервер, ни ключи не публиковались в интернете. Публичный репозиторий содержит исходники и учебные материалы, а не работающий публичный сервис.
